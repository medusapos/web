## Checked against the source

- **Too many version statements on the home page (sceptic, visitor,
  designer, owner): true.** #105's caption sentence made four. Spec AA
  reverts it.
- **Registers never says how to move the one register between counter and
  phone (owner): true.** The page explains only Take over, which leaves the
  old session with no Z report. App ADR 0022 line 8 says an open session
  refuses every other till's open, so the everyday way is close, then open.
  Spec BB.
- **The quick start never says the products must be in the sales channel
  (sceptic): true.** Only At the till says it, in passing ("Products your
  sales channel doesn't sell are hidden"). The app's `docs/QUICKSTART.md`
  lines 77–81 tie the publishable key to "what the channel sells". Spec CC.
- **Code blocks wrap mid-token on phones (designer): true, kept.** Wrapping
  is the round 3 choice (#53) that ended sideways scrolling on phone.
- **Make a sale says "choose a register" (visitor): true.** Every store has
  one, Register 1. A candidate.
- **Plugin setup's order differs from the quick start (owner): true.** Plugin
  setup says install and migrate, then register in `medusa-config.ts`; the
  quick start registers before the migration. A candidate.

## Not put on the site

- **Who builds and supports MedusaPOS (sceptic, visitor).** A maintainer or
  support line is a new claim about the product, so it goes to the front
  desk, not shipped.
- **Whether a POS cashier can approve their own shortfall (owner).** It
  needs the app's RBAC facts first.
- **The deployed build identifier on the home page (developer).** Ruling A
  makes no promise about the hosted build, and a build id beside the caption
  would add another version statement.
- **A white card surface and larger lead cards in the feature grid
  (designer), a larger phone screenshot (sceptic), a tighter hero crop
  (visitor).** These are visual changes; they go to the front desk with
  before/after.
