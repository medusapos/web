## Checked against the source

- **The home page doesn't say one register means one till takes payment
  (owner, sceptic): true.** Registers says a till opens Register 1 before
  taking payment (line 19), and that a second till can't open it while
  another holds it (line 64; ADR 0022 line 8). Spec KK carries this to the
  home bullet.
- **The changelog contradicts itself on SQLite (sceptic): false, but it reads
  that way.**
  - 0.1.0 already used SQLite-wasm: the `medusapos/app` v0.1.0 release note,
    line 16, and `@tallyui/storage-sqlite` 2.0.0 pinned at `v0.1.0`.
  - The "pre-SQLite" builds are the Dexie builds from before 0.1.0 (#160).
  - Spec LL names them.
- **Troubleshooting's "see Plugin setup" points to a page with no update
  steps (owner): true.** They are under Changelog → Update the plugin. Spec MM.
- **The quick start's local port is 9100 (visitor): true.** Medusa's default
  is 9000. Spec MM.
- **The quick start doesn't say one stock location per channel
  (developer): partly.** Limitations says it. Left for a later round.

## Found

- **The front desk ruled on npm (18 Nov): install the plugin from npm.**
  - `npm view @medusapos/medusa-plugin version dist-tags` gives 0.2.4, `latest`.
  - npm's 0.2.3 is byte-identical to the v0.2.0 release asset (sha1
    `db41b1ba`).
  - 0.2.4 comes from tag `plugin-v0.2.4` (#267, "README Install section, first
    CI-published release") and has no release note. No source says app 0.2.0
    was checked against 0.2.4.
  - Spec NN therefore installs `@medusapos/medusa-plugin@0.2.3`.
  - 0.1.0 is not on npm, so the 0.1.0 changelog record keeps its tarball
    command.
- The changelog's "the only released plugin with the register take-over" was
  stale once 0.2.4 shipped. Spec NN makes it "because it has the register
  take-over".
