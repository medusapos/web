## Checked against the source

- **Which build app.medusapos.com serves (sceptic trust 6, designer): a real
  gap.** At `medusapos/app` 781cd94:
  - ADR 0005 says "Every push to `main` deploys to production".
  - `apps/expo/vercel.json` serves the app and the demo from one deployment.
  - So tills run the latest main build, not 0.2.0. The site's "the version
    you install today" was wrong.
  - Plugin 0.2.3 still works with it. Verified approval turns on only at
    register contract 3 (`register.tsx:146`), and 0.2.3 accepts
    `order.create` 1 to 5.
  - The order note is the exception. The hosted app shows the box, but the
    note goes only as `order.create` 7 (ADR 0024 lines 12–15), so it never
    reaches a 0.2.3 store.
  - The front desk ruled: say so, tie the feature list to 0.2.0, and promise
    no pinning. That is spec TT.
- **The phone hero keeps the desktop caption (designer, sceptic, visitor):
  true.** Spec OO, #95.
- **"Keyboard-wedge" is unexplained (owner): true.** At the till already says
  it plainly. Spec RR, #96.
- **"Super admins keep their access" then "Anyone without a POS role" is
  refused (developer): true as written.** Spec SS, #97.
- **Footer tap targets are about 20 px (owner, visitor): false.** Measured on
  production at 320 and 390 px: TallyUI, VendurePOS, Docs, Help and Changelog
  are each 44 px tall (`inline-block py-3`).
- **Code blocks break `medusa-plugin` at its hyphen on phone (designer):
  true, kept.** The wrap is deliberate (`app/global.css`, `pre-wrap` with
  `overflow-wrap: anywhere`), so no command needs sideways scrolling. The
  break falls at a hyphen the command already has.
